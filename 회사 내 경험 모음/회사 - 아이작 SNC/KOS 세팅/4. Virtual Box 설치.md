|                  |                                                                                             |

## 1단계: Visual C++ Redistributable 설치 (필수)

VirtualBox 설치 전에 **Microsoft Visual C++ Redistributable**이 먼저 설치되어 있어야 합니다. 없으면 설치 시작 시 아래와 같은 경고가 뜨고, 무시하고 진행하면 "Installation failed!" 오류가 납니다.

> Oracle VirtualBox 7.2.20 needs the Microsoft Visual C++ 2019 Redistributable Package being installed first.

1. 아래 주소에서 파일을 받습니다. (일반 PC는 **X64**)  
    https://aka.ms/vc14/vc_redist.x64.exe  
    안내 페이지: https://learn.microsoft.com/ko-kr/cpp/windows/latest-supported-vc-redist
2. `vc_redist.x64.exe`를 실행해 설치합니다. "이미 설치되어 있다"는 메시지가 나오면 **복구**를 누릅니다.
3. **PC를 재시작**합니다.

> **시행착오 포인트:** 2015-2022 통합 버전 하나가 "2019" 요구 조건을 충족합니다. 별도로 2019 버전을 찾을 필요가 없습니다.

> ARM64 기기라도 X64 패키지에 ARM64 바이너리가 포함되어 있어 X64 파일 하나로 충분합니다. 다만 VirtualBox 자체의 ARM 지원은 제한적이니 설치 파일이 호환되는지 확인하세요.

## 2단계: VirtualBox 설치

1. VirtualBox 설치 파일을 **우클릭 → 관리자 권한으로 실행**합니다.
2. 기본 옵션 그대로 **다음**을 눌러 설치를 완료합니다.
3. 설치 중 네트워크가 잠시 끊긴다는 안내가 나올 수 있습니다. 정상이므로 **예**를 선택합니다.

### 설치 중 오류가 날 때

|   |   |   |
|---|---|---|
|증상|원인|해결|
|VC++ 필요 경고 후 "Installation failed"|Redistributable 미설치|1단계 수행 후 재시작, 다시 설치|
|VC++ 설치했는데도 같은 오류|기존 VC++ 손상|설정 → 앱 → 설치된 앱에서 "Microsoft Visual C++ 2015-2022 Redistributable" 선택 → 수정 → **복구** 후 재시작|
|VC++ 설치 자체가 실패|Windows 업데이트 밀림|설정 → Windows 업데이트에서 대기 중인 업데이트 설치 후 재시작|
|계속 오류|Windows Installer 서비스 문제|`Win+R` → `services.msc` → "Windows Installer" 상태 확인, 로그는 `%TEMP%` 폴더의 `VirtualBox_..._.log` 파일|

## 3단계: 새 가상 머신 만들기

VirtualBox를 실행하고 **새로 만들기**를 누른 뒤, 화면별로 아래 값을 선택합니다.

### 3-1. 이름 및 운영 체제 화면

|   |   |
|---|---|
|항목|값|
|이름|`jak-virtual-pc` (원하는 VM 이름)|
|폴더|기본값 (`C:/Users/<사용자>/VirtualBox VMs`)|
|ISO 이미지|준비한 Windows 11 ISO 파일 선택|
|종류 / 버전|**Windows 11 (64-bit)** — ISO를 선택하면 파일명을 읽고 자동으로 채워짐|
|Skip Unattended Installation|**체크하지 않음** (무인 설치 사용)|

> **참고:** ISO는 따로 입력하는 칸이 아니라, 이 화면의 **ISO 이미지** 칸에 지정하면 됩니다. 파일명이 `Windows11_Client_x64_...` 형식이어야 OS가 자동 인식됩니다. 파일명을 바꾸지 마세요.

### 3-2. 무인 게스트 OS 설치 화면

|   |   |
|---|---|
|항목|값|
|사용자 이름|`kos-pc` (Windows에 만들어질 계정 이름)|
|비밀번호|직접 설정 (별도로 기록해 둘 것)|
|제품 키|비워 둠 (정품 인증은 나중에)|
|Host Name/Domain Name|기본값 (`<VM이름>.myguest.virtualbox.org`)|
|게스트 확장 설치|**체크**|
|게스트 확장 ISO|기본값 (`C:\Program Files\Oracle\VirtualBox\VBoxGuestAdditions.iso`)|
|Install in Background (백그라운드에서 설치)|체크하지 않음|

### 3-3. 하드웨어 화면

|   |   |
|---|---|
|항목|값|
|기본 메모리|4096 MB|
|프로세서|4개|
|Use EFI (EFI 사용)|**체크**|

> Windows 11은 TPM과 보안 부팅을 요구합니다. VirtualBox 7.x가 이를 자동 처리하므로 EFI만 체크하면 됩니다.

|   |   |
|---|---|
|항목|값|
|가상 하드 디스크 새로 만들기|**80 GB**|

### 3-5. 요약 화면 확인

마지막 요약 화면이 아래와 같은지 확인하고 **마침**을 누릅니다.

|   |   |
|---|---|
|항목|값|
|가상 머신 이름|jak-virtual-pc|
|게스트 운영 체제 종류|Windows 11 (64-bit)|

## 4단계: 설치 진행 확인

**마침**을 누르면 VM이 자동으로 부팅되고 Windows 설치가 시작됩니다.

- 무인 설치이므로 언어, 파티션, 계정 설정을 직접 입력하지 않아도 됩니다. 한동안 아무것도 건드리지 말고 기다립니다.
- 설치 중 VM이 여러 번 재부팅되는 것은 정상입니다.
- 설치가 끝나면 바탕화면이 나타나고, 게스트 확장이 설치되면서 화면 해상도와 마우스 연동이 자연스러워집니다.
- 제품 키를 입력하지 않았으므로 정품 인증은 되지 않은 상태입니다.

> **시행착오 포인트:** ISO의 빌드 번호(예: 26300)가 정식 배포판이 아닌 **Insider(미리보기) 빌드**일 수 있습니다. 이 경우 무인 설치가 중간에 멈추거나 오류가 날 수 있습니다. 그럴 때는 VM을 삭제하고 다시 만들면서 3-1 화면에서 **Skip Unattended Installation**을 체크한 뒤, Windows 설치 화면에서 수동으로 진행합니다.

## 5단계: VM이 느리거나 실행되지 않을 때

Windows의 **메모리 무결성(코어 격리)** 과 **Hyper-V 하이퍼바이저**가 켜져 있으면 VirtualBox가 매우 느리거나 VM이 시작되지 않을 수 있습니다. 증상은 다음과 같습니다.

- VM이 극도로 느리다.
- 시작 시 가상화 관련 오류가 뜬다.
- VirtualBox 화면 우측 하단에 거북이 모양 아이콘이 보인다.

이 경우 별도 문서 **"메모리 무결성 및 하이퍼바이저 비활성화"** 를 참고해 아래 순서로 진행합니다.

1. 메모리 무결성 끄기
2. `bcdedit /set hypervisorlaunchtype off`, `bcdedit /set vsmlaunchtype off` 실행
3. 재부팅 후 `systeminfo`로 상태 확인
4. 안 꺼지면 DG Readiness Tool, 선택적 기능 해제, 레지스트리 수정 순으로 시도

> 하이퍼바이저를 끄면 **WSL2, Docker Desktop, Windows 샌드박스**는 동작하지 않습니다.

## 참고 사항

- VM 파일은 `C:/Users/<사용자>/VirtualBox VMs/<VM이름>` 폴더에 저장됩니다. 백업하거나 옮길 때 이 폴더를 기준으로 합니다.
- 가상 디스크는 처음에는 작게 시작해서 사용량에 따라 커지지만, 최대 80GB까지 늘어날 수 있으니 호스트 디스크 여유 공간을 확인하세요.
- VM 설정(메모리, CPU)은 **VM을 완전히 끈 상태**에서 설정 메뉴로 변경할 수 있습니다.
