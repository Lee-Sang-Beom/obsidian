 > 미리보기는 사용자 브라우저 기준 표시일 뿐이며 서버 저장 전 검증을 대체하지 않는다는 점 명시

- 프론트에서 수행하지 않는 검증 항목 정리
 > 카카오톡 등 메신저/커뮤니티 프로그램에서 가져온 이미지에서 발생할 수 있는 문제 정리: MIME 누락, alias MIME(image/jpg, image/pjpeg, image/x-png), 확장자와 실제 내용 불일치, 브라우저 미리보기는 되나 서버 decode 실패, 다운로드/복사 과정에서의 파일 body 손상, HEIC/HEIF 등 비허용 형식 유입
 > 현재 프론트 미수행 검증: MIME alias 정규화, 파일 signature 검사, 브라우저 decode 검사, 손상 이미지 판별, 확장자와 실제 파일 body 불일치 판별
 > 따라서 백엔드는 프론트의 File.type 기반 검증을 신뢰하면 안 된다는 점 명시

- 백엔드 image-assets 업로드 API 구현 시 참고사항 정리
 > 별도 수행해야 할 검증: 업로드 크기 제한, 허용 MIME 제한, MIME alias 정규화, 파일 signature 검사, 확장자와 실제 파일 내용 불일치 처리, 서버 측 이미지 decode 가능 여부 검사, animated image 허용 여부, width/height 및 total pixel 제한, 저장소에 기록할 content type 정규화, 악성 파일 및 polyglot 파일 방어
 > MIME alias 정규화 기준: image/x-png -> image/png, image/jpg -> image/jpeg, image/pjpeg -> image/jpeg, image/jpeg -> image/jpeg, image/webp -> image/webp
 > 파일 signature 기준: PNG는 첫 8 byte가 PNG signature와 일치, JPEG는 첫 3 byte가 FF D8 FF와 일치, WEBP는 RIFF container이고 8~11 byte가 WEBP와 일치
 > signature 검사 적용 시 확장자보다 실제 파일 body를 우선
 > 실패 응답은 기존 백엔드 envelope인 { error, meta } 형태를 유지하도록 안내
