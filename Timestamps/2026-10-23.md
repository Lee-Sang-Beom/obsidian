0. 지금 진행하는 개발 방식은 작업할때 토큰 너무잡아먹는다. 테스트할때 뭐 이상한 파일 100개씩 너무 많이 생성하고 없애는 방향으로 테스트하는 것 같은데, 조금 간소화한 버전으로 TDD/DDD하면서 개발하는 형태로 진행하자. 이것도 docs/guide쪽에 따로 SKILL이나 컨벤션 형태로 지정해야한다면 생성하고 적용해라

1. 기존 진행하던 작업 진행

2. 프론트 영상생성 기본적으로 r2v로 연결
   
3. 영상 생성 작업 페이지에서 입력 이미지에 대한 분석 캐시 초기화 버튼이 있어. 이거 프론트에서 필요한 버튼이 아니고 백에서 실행하는 거라는데 없애야함. 일단 근데 확인은 해보자.
   
4. 프론트 features 하위 구조 개선 필요
	- features/하위는 기본적으로 페이지 라우트 구조와 비슷하게 가져감 
		- 예: http://localhost:3000/videos/library 라면 src/features/videos/library 하위에 로직 작성
		  
	- 그런데 지금은 /videos 경로 하위에 /create, /library, /requests만 라우트가 있는데 그 외의 디렉터리 경로가 너무많음. 혼란이 온다.
		- 위 3개 라우트 경로 이외의 나머지는 완전히 공통의 성격이어야 함 
		- 라우트 성격인 것은 현재 구조 그대로 유지
		- 만약, 성격이 공통 컴포넌트, 공통 mappers, 공통 rules 이런 목적으로 해당 depth에 선언되어있다면 폴더명 제일 앞에 `_` 를 붙여야 할 것 같음. (ex: `components -> _components`, `mappers-> _mappers` 처럼)
	
	- 추가적으로 /videos 경로 하위에 /detail이라는 디렉터리가 있는데, 이건 상세 페이지 관련 파일인 것으로 보임. 
		- 보통 Next.js에서 상세페이지같은 걸 구현할 때 지금 구현한 방식이 권장되는 공식 방식인지 한 번 확인해볼 필요가 있음.
		- 특정 라우트 페이지 하위 및 자식 개념에 종속되는 detail와 비슷한 경로의 배치의 디렉터리 구조 배치는 항상 컨벤션에 맞춰야 함.
		  
	- 일단은, /videos 라우트 경로 먼저 확인하고, 완료 시 다른 라우트 경로도 비슷한 문제가 있는지 확인 후 개선 필요
	
	- 그리고 이러한 내용은 컨벤션으로 따라야 한다. docs/guides 하위에 다음의 내용이 기재되어 있지 않으면, 아래의 컨벤션 규칙을 따르게 내용을 추가하자.
		- 지금 위에서 언급한 features 하위 라우트 관련 언급 구조 관련 내용
		- features/ 특정 라우트 경로 하위에 쌓이는 비슷한 성격의 파일이 2개 이상이면 적합한 디렉터리를 새로 만들고 그 안에 배치시켜야한다.
			- 이건 지금 컨벤션 내용에도 기록되어 있는건데, 이를 지켜서 개발하지 않았음.
			- 예시 : `*.rules.ts(rules 디렉터리 생성 후 안에 배치), *.mappers.ts(mappers 디렉터리 생성 후 안에 배치), *.types.ts(types 디렉터리 생성 후 안에 배치)` 
			  
		- 이미 디렉터리가 있지만 그 안에 요소들이 너무많으면 그 안에 또 디렉터리를 만들어야 한다. 
			- 예시: `src/features/videos/detail/mappers`  하위에 매우 많은 요소들 대상 `/bgm-retake`, `/narration` 처럼 비슷한 성격들 묶기
  

5. 기존에 작성된 컨벤션 규칙을 지키지 않은 코드가 있는지 확인하고 수정 진행 필요
