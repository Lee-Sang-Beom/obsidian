

#### Work (프로젝트: 영상 제작 프로젝트)

- 프론트엔드
  - workos redirect 주소를 다시 내부 ip쪽으로 연결
  - `/studio` 대시보드 영상 목록 API 연동 준비
    - `GET /v1/video-requests` 계약 문서 확인
    - 진행 중/완료 영상 목록 응답 타입 추가
    - 영상 요청 목록 조회 service 함수 추가
    - Studio 전용 React Query hook 및 query key 추가

  - A4 API 프록시 구조 보완
    - `/api/a4` 요청이 WorkOS AuthKit 인증 proxy에 걸리지 않도록 예외 처리
    - 브라우저 요청이 Next Route Handler를 통해 A4 백엔드로 전달되도록 proxy matcher 정리

  - `/studio` 완료 영상 영역 API 연동
    - 완료 영상 목록 영역에서 `GET /v1/video-requests` 응답의 `completed` 데이터 표시
    - 완료 영상 카드 UI 추가
    - 완료 영상 재생/다운로드용 proxy URL 처리 추가
    - API 응답 DTO를 Studio 표시 모델로 변환하는 mapper 추가


- 백엔드
  - `GET /v1/video-requests` 영상 목록 조회 API 추가
    - 인증된 사용자 기준으로 본인 `VideoRequest`만 조회되도록 owner 격리 처리
    - 응답을 `in_progress`와 `completed`로 분리해 프론트 대시보드용 형태로 구성
    - `master_video_asset_id`가 있는 요청은 완료 항목으로 분류
    - 완료 항목에 영상 재생용 `content_url`과 `video` descriptor 포함
    - 요청별 실행 상태를 `segment_executions`와 Generation 상태 기준으로 계산해 진행률 제공
    - 분석/컴파일/마스터 영상 생성/구간 실행 실패 정보를 dashboard item의 `error`로 노출
    - 프론트엔드 구현을 위한 `GET /v1/video-requests` 계약 문서 작성

  - 목록 조회 안정성 보완
    - 연결된 Generation 조회 실패가 목록 전체 실패로 번지지 않도록 항목 단위 오류로 처리
    - `master_video_asset_id`가 있지만 실제 video asset 조회에 실패한 경우 완료 목록이 아닌 진행 목록에 오류 상태로 표시
    - 깨진 실행 포인터, 누락된 Generation, 누락된 master video asset 케이스 처리

  - VideoRequest 서비스 확장
    - `FileSystemVideoRequestService.list()` 추가
    - 기존 filesystem 저장 방식과 동일하게 owner hash 기준 필터링 및 최신순 정렬 적용
