아래 순서로 세 계정을 각각 테스트하면 됩니다. **현재는 프론트의 화면·요청 제한을 확인하고, 백엔드 직접 호출의 권한 검증은 별도로 기록**하세요.

계정은 `조회자(viewer)`, `운영자(manager)`, `관리자(admin)`를 준비하고, 혼동을 피하려면 서로 다른 브라우저 프로필을 사용하는 것이 좋습니다.

**5. 권한·세션 변경 — 중요**

동일 브라우저에서 순서대로 확인합니다.

- [ ] 관리자 로그아웃 → 조회자 로그인 시 관리자 메뉴·버튼·기존 창이 남지 않는다.
- [ ] 조회자 로그아웃 → 운영자 로그인 시 허용된 기능이 표시된다.
- [ ] 편집 중 같은 사용자 권한을 재조회하면 입력이 유지된다.
- [ ] 편집 중 권한이 회수되면 창·변경 기능이 사라진다.
- [ ] 이전 계정의 늦은 응답이 새 계정 화면·알림·데이터에 반영되지 않는다.
- [ ] 토큰 갱신 중 다른 조회가 완료돼도 정상 결과를 받을 수 있다.
- [ ] 세션 만료와 권한 부족 안내가 구분된다. 권한 부족 때문에 불필요하게 로그아웃되지 않는다.

역할 변경이 서버에서 세션을 폐기한다면 **재로그인 안내가 나오는 결과도 계약과 대조해 판단**해야 합니다.

**6. 권한 확인 실패**

- [ ] `/me` 조회 중에는 보호된 변경 UI가 먼저 나타나지 않는다.
- [ ] `/me` 실패 시 이전 권한으로 계속 조작할 수 없다.
- [ ] 재시도 후 정상 권한을 확인하면 화면이 복구된다.
