
현재 로컬 Docker의 볼륨 연결과 코드의 저장 방식을 확인해, 사용자 정보·작업 기록·영상 파일이 각각 어디에 저장되는지 정리하겠습니다.

현재는 **사용자·인증 정보는 PostgreSQL DB에, 영상·이미지·작업 기록은 파일 저장소에 나누어 저장**합니다.

예를 들어 “누가 만든 영상인가?”는 DB의 연결 정보를 보고, “영상 파일은 어디 있는가?”는 파일 저장소에서 찾는 구조입니다.

**사용자 관련 정보는 PostgreSQL에 저장됩니다.**

| 데이터          | 저장 테이블                                           | 주요 내용                              |
| ------------ | ------------------------------------------------ | ---------------------------------- |
| 사용자 계정       | `cms_users`                                      | 이메일·이름·전화번호·권한·비밀번호 해시             |
| 로그인 세션       | `cms_user_sessions`                              | 사용자 연결, refresh token 해시, 만료·폐기 시각 |
| 로그인 이력       | `cms_login_audit_logs`                           | 로그인 성공·실패, IP, 접속 정보               |
| 영상 요청 생성자    | `cms_video_request_creators`                     | 생성 요청 ID와 사용자 ID 연결                |
| 완성 영상 사용자 연결 | `cms_user_completed_videos`                      | 사용자·영상·원본 요청 연결                    |
| 영상 삭제 기록     | `cms_video_deletion_logs`, `cms_video_deletions` | 삭제 결과·수행자·시각·이유                    |

비밀번호는 입력한 문자열 그대로 저장하지 않고 **Argon2 해시**로 저장합니다. 로그인할 때 입력한 비밀번호가 저장된 해시와 맞는지 검사합니다.

**영상과 제작 과정은 파일로 저장됩니다.**

백엔드 컨테이너 안에서는 다음 경로를 사용합니다.

```text
/data/
├─ video-requests/         요청·프롬프트·분석 결과·작업 상태
├─ execution-generations/  구간별 실행 계획·워크플로·실행 상태
├─ video-revisions/        수정 요청·수정 계획·결과 연결 정보
├─ video-assets/           생성된 영상 파일과 메타데이터
├─ image-assets/           업로드·생성 이미지와 메타데이터
└─ brand-profiles/         브랜드 관련 데이터
```

작업 기록은 주로 **JSON 파일**, 실제 영상은 **MP4 파일**입니다. 영상 한 개는 개념적으로 다음처럼 저장됩니다.

```text
video-assets/
├─ vas_영상ID.mp4     ← 실제 영상
└─ vas_영상ID.json    ← 영상 설명 정보
```

JSON에는 영상 ID, 파일명, 크기, 체크섬, 원본 요청 ID, 생성 시각 등이 들어갑니다. 따라서 영상 목록을 표시할 때는 **요청 기록·영상 메타데이터·DB의 사용자 연결 정보**를 함께 읽습니다.

이 경로는 [Compose 설정](D:/lee/company/project/ijaksnc_project/tf_ai_group/Star_ai/compose.yaml:26)에 정의돼 있습니다.

**그 파일들이 실제로 보관되는 장소는 로컬 PC와 GPU 서버가 다릅니다.**

| 환경                   | 영상·작업 파일                  | PostgreSQL 데이터                |
| -------------------- | ------------------------- | ----------------------------- |
| 이 PC의 Docker         | `star_ai_star_ai_data` 볼륨 | `star_ai_star_ai_postgres` 볼륨 |
| `.21` GPU 서버의 기록상 구성 | `/data/star_ai/data`      | `/data/star_ai/postgres`      |

```
21번 서버 컴퓨터
│
├─ /data/star_ai/data/
│    → 우리 서비스의 작업 자료와 결과물
│      요청 내용, 사진, 생성된 음성, 완성 영상 등
│
├─ /data/star_ai/postgres/
│    → PostgreSQL이 사용자·로그인·영상 연결 정보를 저장하는 곳
│
└─ /home/ijak/comfyui/
     ├─ models/   → AI 모델 파일
     ├─ input/    → AI 작업에 사용할 사진·음성 등의 재료
     └─ output/   → AI가 생성한 작업 결과
     
예를 들어 사용자가 자동차 광고를 만들면 이렇게 진행됩니다.
1. 백엔드가 광고 요청 내용을 /data/star_ai/data/에 기록합니다.
2. ComfyUI에 사용할 사진·음성 등의 재료를 전달합니다. 이 재료가 ComfyUI의 input/에 놓입니다.
3. ComfyUI가 models/의 AI 모델을 불러와 영상을 만듭니다.
4. 생성된 영상이 ComfyUI의 output/에 저장됩니다.
5. 백엔드가 그 결과를 가져와 /data/star_ai/data/video-assets/에 저장하고, 영상 라이브러리에서 조회하도록 연결합니다.
따라서 ComfyUI의 output/은 AI 작업 결과가 나오는 곳, 백엔드의 video-assets/는 서비스가 완성 영상을 관리하는 곳입니다. 결과를 가져오는 과정에서 같은 내용의 파일이 양쪽에 남을 수 있습니다.
```

로컬의 **볼륨(volume)**은 Docker가 관리하는 영구 저장 공간입니다. 백엔드 컨테이너의 `/data`를 열면 실제로는 `star_ai_star_ai_data` 볼륨을 읽는 것입니다.

이 PC에서는 프로젝트 소스 폴더와 분리된 **Docker Desktop의 Linux 디스크 내부**에 데이터가 보관됩니다. Windows에서 그 디스크 파일이 놓이는 위치는 Docker Desktop 설정에 따라 달라집니다.

서버 쪽은 지정된 실제 폴더를 컨테이너에 연결합니다. 예를 들어 서버의 `/data/star_ai/data/video-assets`가 백엔드 안에서는 `/data/video-assets`로 보입니다. [서버 저장 경로 기록](D:/lee/company/project/ijaksnc_project/tf_ai_group/Star_ai/docs/services/GPU_서버_이식_목록.md:124)

**ComfyUI에도 별도의 작업 파일이 생깁니다.**

GPU 서버에는 ComfyUI의 `input/`, `output/` 폴더가 있고, 생성에 사용한 입력 파일과 중간·출력 결과가 남을 수 있습니다. 백엔드는 생성 결과를 회수해 자신의 영상 저장소에 저장합니다.

즉, 데이터 보관 장소는 크게 다음 세 군데입니다.

```text
PostgreSQL       → 사용자·인증·영상 연결·삭제 기록
백엔드 저장소     → 요청 JSON·이미지·음성·완성 영상
ComfyUI 저장소   → AI 실행 입력·중간 결과·출력 파일
```

그래서 어제 **컨테이너와 구형 이미지를 삭제해도 데이터가 유지된 것**입니다. 데이터를 별도 볼륨에 보존한 채 실행 프로그램만 교체했습니다.

백업하거나 다른 서버로 옮길 때도 **DB와 백엔드 파일 저장소를 함께 보존해야** 사용자와 영상의 연결까지 복원할 수 있습니다.

참고로 지금은 Docker 엔진에 연결되지 않아 실시간 내부 조회는 하지 못했습니다. 로컬 볼륨명은 어제 실제 확인한 연결 기준이고, 나머지는 현행 코드와 서버 운영 기록 기준입니다.
